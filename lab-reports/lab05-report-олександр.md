## 1. Мета роботи
Набути практичних навичок проєктування та реалізації REST API для вебзастосунку на базі Flask, навчитися повертати структуровані дані у форматі JSON, коректно використовувати методи протоколу HTTP (`GET`, `POST`, `PUT`, `DELETE`) та коди відповідей (`200`, `201`, `204`, `400`, `404`, `405`, `500`), автоматично документувати API за допомогою бібліотеки `flasgger` (Swagger UI), здійснювати валідацію вхідних даних та проводити тестування у клієнті Postman/Bruno.

## 2. Особистий внесок у командну роботу (Частина 1 — 50%)

У рамках розподілу завдань у команді з двох осіб мною виконано першу половину проєкту:

1. **Архітектура REST API та інтеграція (`app.py`, `routes/api_v1.py`, `routes/api_v2.py`):**
   - Створено модульні Blueprint-и `api_v1` (префікс `/api/v1`) та `api_v2` (префікс `/api/v2`).
   - Реалізовано централізовані глобальні обробники помилок для запитів `/api/*` у суворому форматі JSON (`400 Bad Request`, `404 Not Found`, `405 Method Not Allowed`, `500 Internal Server Error`).
   - Налаштовано параметр `app.config['JSON_AS_ASCII'] = False` для правильного відображення українських символів.

2. **Рівень 1 (Базовий REST API для сутностей Products та Feedbacks — 7 endpoints):**
   - `GET /api/v1/products` — список усіх товарів з фільтрацією за категорією (`?category=`), повнотекстовим пошуком (`?search=`) та фільтрацією за ціною (`?min_price=`, `?max_price=`).
   - `GET /api/v1/products/<id>` — отримання конкретного товару за ідентифікатором (повертає 200 або 404 у JSON).
   - `POST /api/v1/products` — створення нового товару з поверненням статусу `201 Created`.
   - `PUT /api/v1/products/<id>` — повне оновлення інформації про товар.
   - `DELETE /api/v1/products/<id>` — видалення товару з поверненням статусу `204 No Content`.
   - `GET /api/v1/feedbacks` — отримання списку відгуків клієнтів.
   - `POST /api/v1/feedbacks` — додавання нового відгуку.

3. **Рівень 2 (Інтерактивна документація Flasgger / Swagger UI):**
   - Інтегровано бібліотеку `flasgger`.
   - Для кожного ендпоінта написано OpenAPI/Swagger docstring у форматі YAML з описом параметрів, тіла запиту, типів даних, відповідей та прикладів.
   - Документація доступна за адресою `http://127.0.0.1:5000/apidocs/` з підтримкою тестування через кнопку *Try it out*.

4. **Рівень 3 (Валідація вхідних даних та версіонування):**
   - **Валідація:** перевірка коректності JSON-тіла, обов'язкових полів, довжини рядків, валідності email через регулярні вирази, додатних цін (`price > 0`). У разі помилок повертається `400 Bad Request` з масивом `details`.
   - **Версіонування (API v2):** реалізовано маршрут `GET /api/v2/products` з інформаційним конвертом (envelope) та повноцінною пагінацією (`page`, `per_page`, `sort`, `total_items`, `total_pages`, `has_next`, `has_prev`).

5. **Тестування:**
   - Створено колекцію `postman_collection.json` зі сценаріями перевірки успішних відповідей та обробки помилок.
   - Розроблено автоматизований тестовий модуль `test_api.py` на базі `unittest` (12/12 успішних тестів).

6. **Підготовка матеріалів для напарника:**

## 4. Приклади запитів та відповідей

### 4.1. Отримання товару за ID (GET)
* **Запит:** `GET /api/v1/products/1`
* **Код відповіді:** `200 OK`
* **Тіло відповіді:**
```json
{
  "id": 1,
  "name": "Зимова куртка-пуховик",
  "category": "Куртки",
  "price": 3200.0,
  "description": "Теплий пуховик з водовідштовхувальної тканини.",
  "created_at": "2026-11-18 20:00:00"
}
```

### 4.2. Створення товару з валідацією (POST — 201 Created)
* **Запит:** `POST /api/v1/products`
* **Тіло запиту:**
```json
{
  "name": "Парка аляска",
  "category": "Парки",
  "price": 4200.0,
  "description": "Надзвичайно тепла зимова парка"
}
```
* **Код відповіді:** `201 Created`

### 4.3. Приклад валідації помилки (POST — 400 Bad Request)
* **Запит:** `POST /api/v1/products`
* **Тіло запиту:** `{"name": "", "category": "Куртки", "price": -50}`
* **Код відповіді:** `400 Bad Request`
* **Тіло відповіді:**
```json
{
  "error": "Помилка валідації вхідних даних",
  "details": [
    "Поле \"name\" обов'язкове і має бути непорожнім рядком.",
    "Поле \"price\" має бути додатним числом більше 0."
  ],
  "status": 400
}
```

### 4.4. Версія v2 з пагінацією (GET /api/v2/products?page=1&per_page=2)
* **Код відповіді:** `200 OK`
```json
{
  "version": "v2",
  "pagination": {
    "page": 1,
    "per_page": 2,
    "total_items": 20,
    "total_pages": 10,
    "has_next": true,
    "has_prev": false
  },
  "items": [
    {
      "id": 20,
      "name": "Куртка гірськолижна",
      "category": "Спортивний одяг",
      "price": 5400.0
    },
    {
      "id": 19,
      "name": "Шуба штучна",
      "category": "Зимовий одяг",
      "price": 6200.0
    }
  ]
}
```
