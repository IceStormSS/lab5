# 🧥 Outerwear Shop — RESTful Web API (Лабораторна робота №5)

Вебзастосунок інтернет-магазину верхнього одягу з реалізацією повноцінного REST API на базі фреймворку **Flask**, СКБД **SQLite**, автоматичною документацією **Flasgger (Swagger UI)** та тестуванням через **Postman** / **Bruno**.

---

| :--- | :--- | :--- |

## 🛠️ Використані технології

* **Мова програмування:** Python 3.12+ / 3.14
* **Вебфреймворк:** Flask 3.1 (Blueprints, Request, Response, Jsonify)
* **База даних:** SQLite 3 (з підтримкою `PRAGMA foreign_keys = ON;` та `sqlite3.Row`)
* **Документування API:** Flasgger 0.9.7 (OpenAPI 2.0 / Swagger UI)
* **Тестування API:** Postman / Bruno, модульні тести Python `unittest`

## 🚀 Швидкий запуск проєкту

### 1. Запуск через пакетний файл:
Двічі клікніть по файлу **`run.bat`** у корені папки. Він автоматично підготує середовище, запустить сервер Flask та відкриє браузер.

### 2. Запуск через термінал:
```powershell
# Активація віртуального середовища
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# Запуск сервера
.\.venv\Scripts\python.exe app.py
```

* **Головна вебсторінка магазину:** `http://127.0.0.1:5000/`
* **Інтерактивна документація Swagger UI:** `http://127.0.0.1:5000/apidocs/`
* **Специфікація OpenAPI JSON:** `http://127.0.0.1:5000/apispec_1.json`

## 📊 Таблиця ендпоінтів REST API

### Частина 1 (Виконано — 50%)

| Метод | URL-адреса | Призначення | Тіло запиту | Коди відповідей |
| :---: | :--- | :--- | :---: | :--- |
| `GET` | `/api/v1/products` | Отримати список усіх товарів (фільтрація: `?category=`, `?search=`, `?min_price=`, `?max_price=`) | Немає | `200 OK` |
| `GET` | `/api/v1/products/<id>` | Отримати деталі товару за ідентифікатором | Немає | `200 OK`, `404 Not Found` |
| `POST` | `/api/v1/products` | Створити новий товар (з валідацією полів `name`, `category`, `price > 0`) | JSON | `201 Created`, `400 Bad Request` |
| `PUT` | `/api/v1/products/<id>` | Повне оновлення даних товару | JSON | `200 OK`, `400 Bad Request`, `404 Not Found` |
| `DELETE` | `/api/v1/products/<id>` | Видалити товар з каталогу | Немає | `204 No Content`, `404 Not Found` |
| `GET` | `/api/v1/feedbacks` | Отримати список усіх відгуків клієнтів | Немає | `200 OK` |
| `POST` | `/api/v1/feedbacks` | Додати новий відгук (з валідацією імені, email та тексту) | JSON | `201 Created`, `400 Bad Request` |
| `GET` | `/api/v2/products` | **API v2:** Отримати товари з пагінацією (`?page=1&per_page=6&sort=price_desc`) | Немає | `200 OK`, `400 Bad Request` |

### Частина 2 (Для напарника — 50%)

| Метод | URL-адреса | Призначення | Тіло запиту | Коди відповідей |
| :---: | :--- | :--- | :---: | :--- |
| `GET` | `/api/v1/orders` | Отримати список замовлень (фільтри: `?status=`, `?phone=`) | Немає | `200 OK` |
| `GET` | `/api/v1/orders/<id>` | Отримати замовлення з приєднаними купленими товарами (`order_items`) | Немає | `200 OK`, `404 Not Found` |
| `POST` | `/api/v1/orders` | Оформити нове замовлення (з розрахунком промокоду та зв'язком M:M) | JSON | `201 Created`, `400 Bad Request` |
| `PATCH` | `/api/v1/orders/<id>/status` | Змінити статус замовлення ('В обробці', 'Відправлено' тощо) | JSON | `200 OK`, `400 Bad Request`, `404 Not Found` |
| `POST` | `/api/v1/coupons/validate` | Перевірити промокод на дійсність та отримати % знижки | JSON | `200 OK`, `400 Bad Request` |
| `GET` | `/api/v1/coupons` | Список усіх промокодів магазину | Немає | `200 OK` |
| `GET` | `/api/v1/customers` | Список зареєстрованих клієнтів | Немає | `200 OK` |
| `GET` | `/api/v2/orders/stats` | **API v2:** Агрегована статистика замовлень та сумарна виручка | Немає | `200 OK` |

## 🧪 Тестування REST API

### 1. Автоматизоване тестування через Python
У проєкт включено повноцінний набір тестів, що покриває успішні сценарії, граничні значення та обробку помилок:
```powershell
python test_api.py
```
Результат виконання:
```text
Ran 23 tests in 0.109s
OK
```

### 2. Колекція Postman / Bruno
У корені проєкту розташовано файл **`postman_collection.json`**, який містить:
* Усі підготовлені HTTP-запити для кожного ендпоінта;
* Змінну середовища `{{baseUrl}} = http://127.0.0.1:5000`;
* Вбудовані тести на JavaScript для перевірки статус-кодів (`200`, `201`, `204`, `400`, `404`) та валідності структури JSON-відповідей.

#### Приклади тестових сценаріїв:
1. **Позитивний сценарій (`GET /api/v1/products/1`):**
   * **Запит:** `GET http://127.0.0.1:5000/api/v1/products/1`
   * **Статус:** `200 OK`
   * **Тіло:**
     ```json
     {
       "id": 1,
       "name": "Зимова куртка-пуховик",
       "category": "Куртки",
       "price": 3200.0,
       "description": "Теплий пуховик з водовідштовхувальної тканини."
     }
     ```
2. **Сценарій помилки (`POST /api/v1/products` з від'ємною ціною):**
   * **Запит:** `POST http://127.0.0.1:5000/api/v1/products`
   * **Тіло:** `{"name": "", "category": "Куртки", "price": -100}`
   * **Статус:** `400 Bad Request`
   * **Тіло:**
     ```json
     {
       "error": "Помилка валідації вхідних даних",
       "details": [
         "Поле \"name\" обов'язкове і має бути непорожнім рядком.",
         "Поле \"price\" має бути додатним числом більше 0."
       ],
       "status": 400
     }
     ```

## 📑 Рівні виконання (Критерії оцінювання)

* **Рівень 1 (Базовий REST API):** Реалізовано більше 6 endpoints (усього 8 у Частині 1), суворий JSON-формат, правильне використання методів GET, POST, PUT, DELETE та HTTP-кодів відповідей.
* **Рівень 2 (Документація Flasgger):** Інтегровано бібліотеку `flasgger`, створено OpenAPI-описи для всіх маршрутів зі схемами тіла запитів, параметрів та прикладів.
* **Рівень 3 (Додаткове завдання):**
  * **Валідація:** Перевірка типів, обов'язкових полів, додатних чисел та формату email регулярними виразами.
  * **Версіонування:** Реалізовано версії `/api/v1` та `/api/v2` (у v2 додано пагінацію, сортування та інформаційний конверт).
  * **Обробка помилок:** Глобальні обробники `400`, `404`, `405`, `500` повертають структурований JSON.
